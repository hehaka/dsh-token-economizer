## Facts

### Q1: web transport and API (read from the browser's own calls and from `dsh-api-session-controller`)
- Server line on stdout: `dsh web: http://127.0.0.1:<port>/?token=<launch token>` (`--port 0 --no-open`). The token is a secret: never print it.
- Auth for a non-browser script: `GET /?token=<t>` with `redirect: 'manual'` returns 303 + `Set-Cookie: dsh-auth-<hash>=...`; send that cookie (`cookie` header) on every API call. Without the token the page/API answers 401 (`dsh-client-connection/lib/index.js`: `authorizeIndex`, cookie prefix `dsh-auth-`; `/connect` is a second route for API operators, not used).
- RPC: `POST http://127.0.0.1:<port>/api/<method>`, body `{"type":"client-request","rpcId":"<uuid>","method":"<method>","payload":{"args":{...}}}`; reply `{"type":"server-response","rpcId":...,"result":{"ok":true,"value":{...}}}` or `"result":{"ok":false,"error":{"code","message","details"}}`. Streams use the WebSocket `ws://127.0.0.1:<port>/api/remote.mux` (`{"type":"open","streamId","endpoint":"session/control"|"$events"|"workspace/follow",...}`).
- Methods seen (exact `args`): `workspace/initializeDefault {}`; `session/create {request:{workspaceId}}` -> `{sessionId, agentPreset:"standard"}` (the UI also calls this at page load: a blank session exists before any prompt; `create` may reuse a blank one); `session/selectModel {request:{sessionId, provider, model, reasoningEffort?}}` -> `{selected:{provider,model}}`; `session/prompt {request:{requestId:<uuid>, sessionId, mode:"queue", content:[{type:"text",text}], clientTimeZone}}` -> `{accepted:true}` (`mode:"followup"` fails: `gateway/input-invalid`, "wire field request failed boundary validation"); `session/modelCatalog {}` -> keys `default, routableProviders, groups, failures`.
- `selectModel` (index.js:795-824) validates availability, appends a `model/selection` event, caches the selection for the next request, and ALSO calls `agentDefaultModel.saveSelection` (it changes the default for sessions created afterwards; harmless only because `DSH_HOME` was isolated). It does not touch `agent.options`.
- The UI model list (stock web, headless models): azure-openai-responses: GPT-6 Luna, GPT-6 Sol, DeepSeek-V4-Pro, DeepSeek-V4.1-Flash, grok-4.7; anthropic: claude-opus-5-5, claude-sonnet-5-5, claude-haiku-5-5 (azure-completitions has no credential and is absent). The UI shows display names; the RPC takes ids (`gpt-6-luna`).
- The plugin's spool file of a session appears at its first recorded message (the prompt), not at session creation (the blank session had none); the endpoint file appears once the first root session exists (page load already creates one).
- Endpoint reply fields: `text`, `usage` (ledger names), `model`, `provider`; error body `{error:{code,message}}` (409 `NO_ROUTE`). Per-session route Map: `routes` in `plugin.mjs`, set by `agent/created` (`agent.options`) and updated by each `request/context`.
- Not tested: `reasoningEffort` in `selectModel`; resuming a stored session in web; two simultaneous prompts.
